# Jana Address

Разбираем адрес, который клиент написал одной строкой, на отдельные поля.
Кейс 1 хакатона Jana Post × Terricon Valley 2026.

Команда: Самир Сайрамбаев (разбор строки), Ерасыл Мартжан (справочник, API, интерфейс, Docker).

```
"Туран 55/6 магазин береке 4подьезд 9этаж"
  → улица Туран, дом 55/6, подъезд 4, этаж 9, ориентир «магазин береке»
```

## Запуск

```bash
docker compose up -d --build
```

Сборка с нуля около полутора минут, старт около 12 секунд. После сборки интернет не нужен.

- API и Swagger: http://localhost:8000/docs (пример запроса уже подставлен)
- Интерфейс: http://localhost:8501 (логин `admin`, пароль `jana-admin`)

Если на машине нет интернета даже для сборки, берите готовый образ:

```bash
docker load -i jana-address-image-final.tar
docker compose up -d
```

## Прогнать свой файл

```bash
curl -X POST http://localhost:8000/api/v1/parse/batch \
  -H "Content-Type: application/json" \
  -d @sample_input.json -o output.json
```

На входе список `{"id", "raw_address"}`, как в `sample_input.json`. На выходе список той же длины и в том же
порядке, поля как в `sample_output.json`. Записи не теряются: если строку разобрать не получилось, поля будут
`null`, а `confidence` низким. Пакетный метод работает без логина и токена.

1000 записей разбираются меньше чем за секунду (лимит 5 минут).

Остальные методы:

| Метод | Зачем |
|---|---|
| `POST /api/v1/parse/batch?debug=true` | то же, плюс откуда взято каждое поле, флаги и неразобранный остаток |
| `POST /api/v1/parse/file` | пакет файлом |
| `GET /api/v1/parse?q=...` | один адрес |
| `POST /api/v1/evaluate` | сравнить разбор с размеченным файлом по весам жюри |
| `POST /api/v1/corrections`, `GET /api/v1/corrections` | правки операторов и их журнал |
| `GET /health` | статус, размер справочника, есть ли сеть |

## Как это работает

```
строка
  → app/noise.py           убираем телефоны, коды домофона, опечатки в «подьезд», «квартра»
  → core/address_parser.py разбираем: область, город, район, улица, дом, кв, подъезд, этаж, ориентир
  → app/pipeline.py        дозаполняем пустые поля по справочнику
  → ответ
```

Ядро (`core/`) написано на чистом Python без зависимостей и покрыто тестами. Оно разбирает то, что
написано в строке: слитное «66квартал», дроби «55/6», `flat`/`kv`, казахский через слэш, невидимые
символы, имена получателей и пометки для курьера (они в ответ не попадают, но видны оператору).

Название улицы отдаём ровно как в строке, без исправления опечаток и падежей. Если улицы нет в справочнике,
система предлагает похожую, но сама не подставляет: решает оператор.

### Справочник

Организаторы справочник не дают, собрали свой:

1. **OpenStreetMap** по Казахстану (дамп Geofabrik). Скрипт `scripts/build_gazetteer.py` вытаскивает
   области, районы, города, микрорайоны, 51 тыс. улиц и 1,2 млн зданий с адресами. Каждой улице и зданию
   район назначается по попаданию точки в полигон района.
2. **КАТО** (классификатор stat.gov.kz) — для сверки. Города и районы совпадают с OSM на 97–100%,
   отчёт в `docs/KATO_CROSSCHECK.md`. Чего нет в OSM, добавили из КАТО.

Всё это лежит в образе (`data/gazetteer.sqlite`, 25 МБ), грузится за пару секунд.

Если района нет в строке, ищем его так:

1. правка оператора для этого дома или улицы;
2. здание «улица + дом» в OSM;
3. улица, если она целиком в одном районе;
4. микрорайон.

Если однозначного ответа нет (улица идёт через несколько районов, а дома нет в OSM), оставляем `null`.
Пустое поле лучше, чем курьер в чужом районе.

Пересобрать справочник (нужен интернет):

```bash
docker compose --profile build run --rm gazetteer-builder
python scripts/build_kato.py
python scripts/export_core_gazetteer.py
docker compose build
```

### Интерфейс

- **Пакетный разбор** — загрузить файл, неуверенные записи сверху, фильтры, правка прямо в таблице, выгрузка JSON/CSV.
- **Умная проверка** — по одной записи; подсвечены конкретные поля, в которых сомневаемся, и почему.
- **Один адрес** — цветная подсветка: какой кусок строки стал каким полем, объяснение каждого поля.
- **Качество** — точность по полям на размеченном файле, частые ошибки, скорость.
- **Журнал правок** — кто, когда и что исправил.

Правки сохраняются и сразу учат справочник: район, который поставил оператор, запоминается для дома и улицы.
Выученное заполняет только пустые поля и не спорит со строкой.

Пароли в `data/users.json` хранятся только хешем (PBKDF2). Добавить пользователя:
`python scripts/add_user.py <логин> <operator|admin> "Имя"`.

## Точность

Размеченных данных у нас не было: в `sample_output.json` одна запись, с ней ответ совпадает полностью.
Поэтому меряем на синтетике. `scripts/gen_synthetic.py` берёт настоящие улицы и дома из OSM и портит их
всеми приёмами из ТЗ: слитное написание, слэш с казахским, опечатки, `kv`, ориентиры, мусорные символы,
телефоны и имена.

| Набор, 3000 записей | По весам жюри |
|---|---|
| Обычная синтетика | 100% |
| «Грязная» (телефоны, имена, опечатки) | 99,9% |
| Район, которого нет в строке | верно 87%, неверно 2%, пусто 11% |

Правим на одних наборах, меряем на новых, которые до замера не открывали. Но синтетика чище настоящих
адресов, так что на реальных данных цифры будут ниже. Наш набор `core/tests/live.json` написан нами,
это регрессионный тест, а не независимая оценка.

Если есть реальные строки без разметки, можно посмотреть слабые места:

```bash
python scripts/audit_train.py путь/к/train.json
```

Скрипт пишет `audit_report.md` с заполненностью полей и частыми остатками. В репозиторий его не кладём,
там куски реальных адресов.

## Проверки

```bash
python scripts/check_all.py            # все тесты, синтетика, восстановление района
python scripts/check_all.py --docker   # плюс проверка Docker без сети
```

Без сети отдельно:

```bash
docker compose -f docker-compose.yml -f docker-compose.offline.yml up -d --force-recreate
python scripts/offline_check.py
```

Контейнеры поднимаются в сети без выхода наружу, скрипт проверяет, что интернета нет, справочник
загружен, 1000 записей укладываются в лимит и интерфейс видит API.

## Структура

```
app/        API, очистка шума, дозаполнение по справочнику, правки, объяснения
core/       ядро разбора строки и его тесты
ui/         интерфейс на Streamlit
data/       справочник OSM, ручной справочник областей, демо-наборы
scripts/    сборка справочника, генератор синтетики, проверки
tests/      тесты через весь пайплайн
docs/       сценарий демо, сверка с КАТО
```

## Правила, которые соблюдаем

- `raw_address` возвращается без изменений.
- Дробь и литера в номере дома не теряются: `1/2`, `12а`.
- Нет сопоставления по `id` и нет таблицы «вся строка → готовый ответ».
- Данные организаторов в репозиторий не попадают (`.gitignore`).
