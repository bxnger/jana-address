# Сценарий защиты (≈ 7 минут)

## Подготовка за 30 минут до выхода

1. Запусти Docker Desktop и дождись статуса Running.
2. В папке проекта выполни:
   ```bash
   docker compose up -d
   ```
3. Открой три вкладки:
   - презентацию;
   - http://localhost:8501 (интерфейс);
   - http://localhost:8000/docs (Swagger).
4. Сбрось демо-правки, чтобы «обучение» показывалось с нуля:
   ```bash
   docker compose down && docker volume rm jana-address_corrections && docker compose up -d
   ```
5. Если Docker не стартует, запасной вариант — загрузить готовый образ:
   ```bash
   docker load -i jana-address-image-final.tar && docker compose up -d
   ```
   Если и это не помогло, показываем запасное видео.

## Демо (2 минуты)

1. **API.** В Swagger открой `POST /api/v1/parse/batch` и вставь:
   ```json
   [{"id": "rec_00417", "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70"},
    {"id": "d2", "raw_address": "Туран 55/6 магазин береке 4подьезд 9этаж"},
    {"id": "d3", "raw_address": "г. Алматы, ул. Жандосова 5, кв 12"}]
   ```
   Что сказать:
   - первый ответ совпадает с эталоном жюри, включая район;
   - у третьего район Бостандыкский найден по номеру дома.
2. **Интерфейс.** Войди как `admin` / `jana-admin`.
   > «Вход для операторов, пароли хранятся только как хеш. Пакетный API для вас открыт без входа».

   Нажми «Загрузить демо-набор». Покажи:
   - метрики;
   - что неуверенные записи идут первыми;
   - сводку «почему неуверенные»;
   - подсвеченный остаток.
   Раскрой «🎛 Фильтры»:
   > «Фильтры по первой букве улицы, городу, району, уверенности и по конкретному полю, которое под сомнением».
3. **Умная проверка.** Открой вкладку «🧭 Умная проверка». Первая запись — «Алматы, ул. Абая, Жандосова, 5, кв 12».
   > «Система подсвечивает не всю строку, а конкретные поля: жёлтые — Улица и Район, с причиной: остался лишний сегмент
   > „Жандосова“, это угол двух улиц. Остальные поля зелёные, и у каждого написано, откуда оно взялось».

   В поле «⚠️ Район» впиши «Бостандыкский» и нажми «💾 Сохранить исправления». Появится «Сохранено… справочник выучил», счётчик прогресса вырастет.
   Затем в «📂 Пакетный разбор» выключи «Только неуверенные» и найди поиском «получатель»:
   > «Имя, телефон и домофон не попали в улицу: колонка "📦 Курьеру", а в ответ жюри они не идут».
   Открой вкладку «📜 Журнал правок»:
   > «Видно, кто, когда и что исправил: правки учат справочник, поэтому важно, кто их сделал».
4. **Объяснимость.** Во вкладке «🔎 Один адрес» вставь `Туран 55/6 магазин береке 4подьезд 9этаж`.
   > «Система не просто выдаёт JSON, а объясняет каждое поле: дом 55/6 — номер с дробью сразу после улицы, подъезд 4 —
   > по ключевому слову, ориентир — по маркеру „магазин“, а город не определён, потому что по одной улице его не восстановить».

   Затем `г. Алматы, ул. Абаяя 10, кв 5`:
   > «Опечатка. Система предлагает „Абая“ из справочника, но сама не подменяет — решает оператор».

   И `Шымкент қаласы, Абай ауданы, Тауке хан даңғылы 5, 3 подъезд, 7 этаж`:
   > «Цветом видно, какой кусок строки стал каким полем. Казахское „Абай ауданы“ записано как в 2ГИС: „Абайский“».
5. **Качество.** Вкладка «📊 Качество» → «▶ Контрольный набор».
   > «На 1000 „грязных“ адресах — точность по каждому полю, частые ошибки с примерами, сколько записей на проверку и
   > скорость: меньше секунды на 1000. Можно загрузить свой размеченный файл — то же самое посчитается на нём».
6. **Офлайн — самый наглядный момент.** Отключи Wi-Fi на ноутбуке и нажми «🔄 Проверить сеть» в шапке.
   Значок в шапке станет зелёным: «🔒 Офлайн: интернета нет — всё работает». Разбери любой адрес или демо-набор.
   > «Все справочники и правила внутри образа. Интернет нужен только чтобы один раз собрать справочник из OSM».

   Надёжнее (на Windows Docker иногда держит сеть и при выключенном Wi-Fi): `docker compose -f docker-compose.yml -f docker-compose.offline.yml up -d`
   и `python scripts/offline_check.py`.

## Вопросы жюри и короткие ответы

- **Откуда справочник?**
  - OpenStreetMap, дамп Geofabrik.
  - Скрипт `build_gazetteer.py` пересобирает его одной командой.
  - Каждой улице и зданию район назначается попаданием точки в полигон района.
- **Что, если адреса нет в OSM?**
  - Поля из строки разбираются всё равно, ядро от справочника не зависит.
  - Район остаётся `null`, мы его не выдумываем.
  - Оператор правит запись в интерфейсе, и справочник это запоминает.
- **Почему не ML-модель?**
  - Данных для обучения не выдали, а правила с тестами прозрачны.
  - Разбор быстрый: 1000 адресов за 0,6 с.
  - Работает без сети.
  - Правки операторов дообучают справочник без переобучения модели.
- **Как считаете точность без train.json?**
  - Генератор берёт реальные улицы и дома из OSM и портит их всеми приёмами из ТЗ, эталон известен заранее.
  - Правим по одним наборам, а меряем на свежем, который не открывали.
  - Свой живой набор держим как регрессионный тест: мы писали его сами, поэтому независимой оценкой его не называем.
- **Что такое confidence?**
  - Это эвристика ядра: флаги вроде «город без г.» или «улицы нет в справочнике» снижают уверенность.
  - 82% ошибочных записей попадают в нижние 20% по уверенности, поэтому оператор проверяет только их.
- **Почему «Абая 10» без района?**
  - В Алматы есть и проспект, и улица Абая в разных районах.
  - Без типа улицы не угадываем: пустое поле лучше неверного района у курьера.
- **Что делаете с именем получателя и телефоном в строке?**
  - Телефон и домофон вырезаются до разбора, имя получателя и пометки («оставить у двери») отделяет ядро.
  - Имя проверяется по справочнику: «Айгерим» — и имя, и мкр, поэтому «г. Алматы, Айгерим, 15» остаётся мкр.
  - Всё это показывается курьеру отдельно и не портит поля адреса.
- **Не подгонка ли это под ответы?**
  - Нет сопоставления по `id` и нет таблицы «строка → ответ».
  - Только правила, справочник и выученные районы по улице и дому.
